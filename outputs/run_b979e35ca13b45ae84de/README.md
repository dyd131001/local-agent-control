# Control Center 개선 시안

[`control-center-prototype.html`](./control-center-prototype.html)을 브라우저에서 열면 7가지 요청 사항을 직접 확인할 수 있습니다. 이 Run에는 기존 앱 소스나 화면 자료가 없어, 시안은 독립형 HTML로 작성했습니다. 데이터는 예시이며 변경 내용은 브라우저의 `localStorage`에 저장됩니다. 실제 앱의 버그가 수정된 상태는 아닙니다.

| 요청 | 시안에서 확인할 위치 |
| --- | --- |
| 대시보드 상태 갱신 | 첫 로드에 즉시 조회하고, 화면 복귀 시 및 15초마다 재조회. 수동 새로고침과 오류 표시 포함 |
| 카테고리 재활성화 | 비활성 보기 → 카테고리 선택 → 다시 활성화 |
| 작업 생성 위치 | 카테고리 화면 오른쪽의 작업 만들기 양식 |
| 카테고리 유형 선택 | 카테고리 만들기의 개발·디자인·리서치·문서·운영·직접 입력 |
| 더보기 정리 | 카테고리의 더보기 → 그리드 버튼을 선택하면 오른쪽 상세 패널 변경 |
| 기존 대화·작업에 요청 연결 | 요청 → 기존 대화 이어가기/질문하기 → 목록 항목 선택 → 내용 등록 |
| 자료 경로 선택 | 카테고리 → 더보기 → 자료 등록 → 폴더 선택 |

## 실제 앱에 연결할 때

- 에이전트 상태: `window.controlCenterApi.getAgentStatus()`가 `{ status: 'online' | 'busy' | 'offline' }`을 반환하도록 연결합니다. 응답 순서가 뒤바뀌어도 오래된 응답이 화면을 덮지 않도록 시안에 요청 번호를 적용했습니다.
- 폴더 선택: 데스크톱 앱이면 `window.controlCenterApi.selectDirectory()`가 `{ name, path }`를 반환하도록 연결합니다. 브라우저에서는 보안상 절대 경로를 읽을 수 없어 폴더 이름만 표시합니다. 지원 브라우저에서는 `showDirectoryPicker`, 그 외에는 폴더 파일 입력을 사용합니다.
- 카테고리·작업·스레드·요청·자료 저장: 현재 `localStorage` 예시 데이터를 실제 API로 교체해야 합니다. 생성, 이름 변경, 상태 변경, 요청 전송, 자료 등록에 서버 검증 및 실패 처리를 추가해야 합니다.

## 검증

- HTML 파일 생성 및 파일 크기 확인.
- 포함된 JavaScript에 `node --check` 실행: 통과.
- Python `HTMLParser`로 HTML 파싱: 통과.
- DOM을 흉내 낸 Node 런타임 점검: 초기 상태 표시, 재활성화 버튼, 작업 양식, 자료 폴더 선택 버튼, 기존 대화 선택 화면 렌더링 통과.
- Playwright 브라우저 테스트는 실행하지 못했습니다. 첫 명령은 셸의 임시 파일 생성이 차단되었고, 기본 Python에는 Playwright 모듈이 없었습니다. Playwright가 설치된 Python으로 작업 공간을 임시 경로로 지정해 재시도했지만 Chromium 실행 파일이 없어 중단되었습니다. 실제 앱 소스와 API도 제공되지 않아 통합 테스트는 수행하지 못했습니다.
